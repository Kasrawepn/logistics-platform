# Repo notes

## Layout
- `dental-clinic/` — the dental clinic site (Persian / RTL, vanilla ES modules, **no build step, no npm deps**).
- `logistics-platform/` — an unrelated earlier app. Do not touch it for dental work.
- `dev-server.mjs` — dependency-free static dev server: serves `dental-clinic/` on port 3000, injects `/config.js`, pushes live reload over SSE.

## Run
```bash
docker compose -f docker-compose.base44.yml up -d
curl -s http://localhost:3000/ | head
```
The web service is `node:22-alpine` with the repo bind-mounted at `/app`; there is nothing to install or build. Edits under `dental-clinic/` reload the preview automatically (the server appends a reload snippet to every HTML response).

## Things that are not obvious
- **three.js is vendored** at `dental-clinic/vendor/three.module.js` (r170). No CDN import at runtime; keep it local so the 3D hero works offline.
- **Routing is hash based**: `#/` (home), `#/booking`, `#/bookings` — see `dental-clinic/js/router.js`. Switching views never reloads the document, which is also how the preview verification drives it.
- **Bookings are client-side** in `localStorage` key `dentorbit.bookings.v1` (`js/store.js`). The status is *derived*, never stored: appointment end (`date` + `time` + 45 min) in the past → «انجام شده», otherwise «در حال انجام».
- **PayPal client ID**: `/config.js` is generated by `dev-server.mjs` from the `PAYPAL_CLIENT_ID` environment variable (platform secret, delivered in `/run/base44/app.env`). The value is never committed. With no client ID the payment step shows a clearly marked «پرداخت آزمایشی» (test payment, nothing charged) instead of pretending to charge.
- Checkout is client-side (`paypal.Buttons` → `actions.order.create` + `actions.order.capture`), so only the public Client ID is required — no server secret.
- **Dentist portrait section** (`#dentist`): its own three.js scene in `js/dentist-scene.js`; the photo lives at `dental-clinic/assets/dr-hosseini.jpg` (downloaded from zahnarztpraxisdrstrahl.de). Replacing that file swaps the 3D portrait. The stage tilts with the pointer and drifts on its own, so it also animates on touch devices.
- **Practice details** (name, address, phone, opening hours) come from zahnarztpraxisdrstrahl.de. `OPENING_HOURS` in `js/main.js` drives the open/closed chip and the "next free slot" card — update it if the hours change.
- **Content extracted from the practice site** lives in `js/content.js` (`PRACTICE`, `SERVICES` — the full 13-item treatment spectrum, `TEAM`, `GALLERY`). `js/home-sections.js` renders the service cards, team cards and opening hours into `#service-grid-more`, `#team-grid` and `#practice-hours`; it runs **before** the reveal `IntersectionObserver` in `main.js`, otherwise the rendered `.reveal` nodes never become visible.
- **All photos are local copies** downloaded from zahnarztpraxisdrstrahl.de into `dental-clinic/assets/site/` (hero/harbour shots, treatment photos, team portraits, implant macros, aligner/gift-voucher graphics). `logo.png` and the smaller implant diagrams are stored but not currently rendered.
- **3D photo gallery** (`#gallery`, `js/gallery-scene.js`): the practice photos are drawn as cropped canvas textures on glass cards arranged on a turning ring; drag to spin, tap a card to bring it to the front, auto-rotation pauses off-screen and with `prefers-reduced-motion`. `canvas.dataset.ready` flips to `"true"` when every texture has loaded, `canvas.dataset.cards` is the card count and `canvas.galleryRotation` exposes the current spin (used by the preview checks). With no WebGL the stage falls back to a flat grid (`renderGalleryFallback`).
- **Card tilt** (`js/tilt.js`) is a pointer-only 3D lean applied to the inner `[data-tilt]` wrapper, so it never fights the `.reveal` transform on the card itself.
- The floating «رزرو نوبت» bar is mobile-only and hidden on the booking/bookings views via `body[data-route]`.
- The site is served from `/` (host port 3000); `dental-clinic/index.html` is the entry.

## How to verify
1. Home: `#orbit-canvas`, `#dentist-canvas` and `#gallery-canvas` all have a WebGL context; `#gallery-canvas` reaches `data-ready="true"` with 9 cards, and dragging it changes `canvas.galleryRotation`. `#service-grid-more` holds 13 cards, `#team-grid` 3 cards, `#practice-hours` 5 rows; no console errors and no horizontal overflow at mobile width.
2. Booking: fill name/phone/date/time → «ادامه و پرداخت» → summary + payment step → test payment → success ticket with a booking code.
3. Bookings page: card shows code, date, time, price; badge «در حال انجام» for a future appointment and «انجام شده» for a past one; the tabs filter the list.
4. Remove any booking you create during testing from `localStorage` afterwards.
